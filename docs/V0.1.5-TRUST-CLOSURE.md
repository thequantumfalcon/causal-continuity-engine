# v0.1.5 Trust-Closure Development Sheet

Status: owner-revised and re-frozen after implementation review (2026-08-22)

Baseline: `main` at `aa29c65`

Policy revision: the local isolated-review deployment and hosted
`cce-integrity-v1` enforcement are explicitly deferred as inactive controls for
v0.1.5.

Release posture: do not publish v0.1.5 until every acceptance criterion below passes

## Objective

Close the release-audit findings without expanding the frozen engine. Every repair
must reproduce the defect, change the deciding path, add a regression test that
fails before the repair, survive an adversarial review of the repair, and preserve
the documented limits of the mechanism.

## Hard constraints

- Keep the runtime standard-library-only.
- Add no subsystem, package module, CLI command, or speculative abstraction.
- Preserve event-log and graph rebuildability.
- Treat missing, skipped, crashed, or inconclusive validation as not-passed.
- The sole approved conditional skip is
  `test_real_seatbelt_denies_child_and_grandchild_when_privileged` on a runner
  that is not a provisioned macOS root-control environment. The skip remains
  not-passed deployment evidence; it never establishes or activates the local
  boundary.
- Keep untrusted prose outside control state; wording cannot elevate source authority.
- Do not weaken proof, verifier, quarantine, invalidation, or completion gates.
- Make one independently reviewable defect/fix/test unit at a time.
- Do not tag, publish, merge, push, or edit announcement material during this program.

## Frozen success criteria

The program is complete only when all of the following are true:

1. Every confirmed finding below has a minimal reproduction and regression test.
2. Resume packets never point at work omitted from the same packet and never claim
   that no work is open when all visible work is blocked.
3. Markdown and MCP projections either expose every promised packet section or
   explicitly disclose non-rendered transport/cryptographic metadata.
4. MCP behavior is read-only, lifecycle-correct, notification-safe, and validates
   JSON-RPC identifiers and parameter shapes.
5. Untrusted or policy-demoted prose cannot create actionable checklist tasks, and
   visible-text screening cannot be bypassed with Unicode format characters.
6. Benchmark metric-gate failure produces a failing process exit status.
7. Development dependency declarations and the reviewed lock file agree exactly.
8. Repository-targeted backfill uses the repository's canonical `.cce` layout and
   cannot forward authorization across a redirect origin.
9. Identity-version, span-provenance, bounded-tail continuation, assumption-filter, and
   invalidation-projection behavior are explicit and regression-pinned.
10. Focused adversarial tests, the complete documented release gate, rebuild/audit,
    and a clean-install built-artifact smoke test all pass from a clean tree.

## Work packages

### Release-gate integrity

- **TC-001 — Development lock drift.** Reconcile `pyproject.toml`,
  `requirements-dev.in`, and `requirements-dev.lock`; make release metadata reject
  any future direct-pin mismatch.
- **TC-002 — Benchmark exit semantics.** Exit nonzero when a scenario fails or any
  metric gate is not `PASS`, even if scenario execution itself completed.

### Repository and packet correctness

- **TC-003 — Backfill repository layout.** With `--dir`, initialize or open the
  canonical `.cce` store used by the CLI; preserve temporary-store behavior when no
  directory is supplied.
- **TC-004 — Retained next-safe-action invariant.** After budget trimming and
  quarantine stripping, a node-backed `next_safe_action` must name a retained open
  task. Otherwise select a retained actionable task or emit a truthful fixed
  disclosure that detail was withheld.
- **TC-005 — All-blocked packet truthfulness.** If open work exists but all visible
  tasks are blocked, state that work is blocked rather than saying no tasks are open.
- **TC-006 — Exhaustive Markdown projection.** Render assumptions, recent context,
  evidence, environment, trust-check outcomes, mission control state, and continuity
  lineage; explicitly classify metadata intentionally omitted from the human view.

### MCP trust boundary

- **TC-007 — Complete packet formats.** Let callers request Markdown or canonical
  JSON without silently dropping packet sections.
- **TC-008 — Read-only server contract.** MCP packet reads must not advance packet
  watermarks or append audit state, including collision paths.
- **TC-009 — Lifecycle state machine.** Require `initialize`, accept the matching
  `notifications/initialized`, and reject tool calls before readiness.
- **TC-010 — Notification semantics.** Requests lacking `id` never receive a response
  and never execute stateful tool paths; explicit `null` is not treated as absence.
- **TC-011 — JSON-RPC validation and ping.** Validate identifier and parameter shapes,
  implement `ping`, and return protocol errors with the correct request identifier.
- **TC-012 — Projection accuracy.** Filter assumptions by status and read nested
  invalidation fields from their canonical shape.

### Ingest and provenance boundary

- **TC-013 — Checklist authority.** Under the strict policy, and for every untrusted
  authority regardless of policy, Markdown checklist items are claims rather than
  actionable tasks, with the demotion recorded.
- **TC-014 — Visible-text injection screening.** Screen canonical visible text after
  removing Unicode format controls; quarantine the whole source block on a match.
- **TC-015 — Raw span coordinates.** Map every extracted statement and context span
  back to offsets in the original source text.
- **TC-016 — Mark/ZWJ continuation guard.** Abstain when the extractor's length
  boundary is followed, through category-Cf controls, by a category-M mark, U+200D,
  or a named variation selector. This is a conservative continuation guard, not
  Unicode grapheme-cluster segmentation.

### Compatibility and transport

- **TC-017 — Identity algorithm version.** Make the extraction identity algorithm's
  version explicit, document the compatibility consequence, and test rebuild and
  upgrade behavior. Any data migration must be deterministic and fail closed.
- **TC-018 — Redirect authorization.** Follow only same-origin HTTPS API redirects;
  never forward the GitHub bearer token to another origin or a downgraded scheme.

## Required test shape for every work package

1. Record the smallest public-path reproduction.
2. Add a regression test and verify it fails against the pre-fix baseline.
3. Apply the smallest repair at the deciding path.
4. Verify the regression and neighboring tests.
5. Attack the repair with at least one adjacent counterexample.
6. Record the mechanism's honest limit if the repair changes a capability claim.

Trust-gate changes must also add the matching planted defect to the gate-coverage
instrument when applicable. Tests must drive the public path rather than validate a
hand-assembled internal object.

## Execution order

1. TC-001–TC-003: make the validation and repository target trustworthy.
2. TC-004–TC-006: repair packet truthfulness before exposing it through MCP.
3. TC-007–TC-012: close the protocol and read-only boundary.
4. TC-013–TC-016: close authority, Unicode, and provenance paths.
5. TC-017–TC-018: pin compatibility and redirect behavior.
6. Run focused adversarial checks, then every documented release recipe.
7. Build a wheel and sdist, install the wheel into a fresh environment, and exercise
   initialization, ingest, resume, MCP handshake/read, rebuild, and audit verification.

## Final verification matrix

- Unit and regression suite: every release-required test passes, with no new
  skip or xfail except the named privileged deployment test on an unprovisioned
  runner. That conditional skip remains an explicit gap and cannot support an
  active-control claim.
- Lint and stdlib dependency scan: pass.
- Conformance corpus: no drift and every expected verdict reached.
- Capability audit: generated documentation remains clean.
- Continuity benchmark: every scenario and every metric gate passes; a planted metric
  failure exits nonzero.
- Event-store checks: rebuild and audit verification pass on the exercised store.
- Packaging: wheel and sdist build; wheel installs without undeclared runtime deps.
- Working tree: only intentional source, test, decision, and generated-document changes.

## Deferred deployment controls

The privileged macOS acceptance test and the external `cce-integrity-v1`
service are deployment evidence, not v0.1.5 publication prerequisites. Until
the exact root-controlled installation passes the privileged test, the local
isolated-review launcher is inactive. Until the external App passes positive,
stale, crash, incomplete, and spoofed-context negative tests and its exact
context is bound in the live ruleset, hosted workflows remain advisory. Neither
absence is counted as a pass, and neither control may be described as active.

## Kill switch and escalation

Stop implementation and write a separate architecture proposal if a repair requires a
new subsystem, storage model, CLI surface, or relaxation of an existing gate. Stop and
reconcile before continuing if the working tree changes concurrently. Publishing and
all other shared-state actions require separate explicit authorization after the final
verification report.
